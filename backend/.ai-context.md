# AI Context: Secure Bank API Proxy

This document provides instant, structured context about this codebase for AI coding assistants (like Cursor, Claude, Copilot, or Gemini).

---

## Project Metadata
- **Project Name**: Secure Bank API Proxy Backend
- **Tech Stack**: Node.js, Express, TypeScript (ES2022, CommonJS), Zod (Validation), Swagger UI Express (Docs), Axios (API client), Helmet (Security headers).
- **Core Purpose**: Acts as a secure middleware proxy that authenticates against downstream banking API endpoints, protects developer credentials from client/frontend exposure, regulates client request traffic, and handles OAuth token lifecycle.
- **Run Modes**:
  - **MOCK**: Default mode when `.env` credentials are empty. Operates stateful, in-memory mocks for accounts, balances, transactions, and beneficiaries.
  - **SANDBOX/PROD**: Proxies requests directly to downstream endpoints using client credential OAuth tokens.

## Architecture Flow

```
[ Frontend Client (e.g. Next.js) ]
         │
         │ (Headers: X-Local-API-Key: <key>)
         ▼
[ Express Router (src/app.ts) ]
         │
         ├───► [ requireLocalAuth (src/middleware/auth.ts) ]
         │      (Verifies proxy-level access key)
         │
         ├───► [ validateRequest (src/middleware/validation.ts) ]
         │      (Validates inputs against Zod schemas)
         │
         ├───► [ Accounts/Transfers Controller (src/controllers/*) ]
         │      (Directs HTTP request/response lifecycles)
         │
         └───► [ BankService (src/services/bank.ts) ]
                ├───► MOCK: Stateful in-memory databases (Balances update on transfers/payments)
                └───► LIVE: Requests token from downstream identity endpoint, caches, and issues API requests.
```

## Interactive Mock Engine Rules
In mock mode, the service holds state in static fields inside `BankService` (`src/services/bank.ts`).
- **Source account**: `:accountId` (e.g. `acc_pb_12345`).
- **Pay Beneficiary**: Deducts `amount` from the source balance and prepends a `DEBIT` transaction to the source transactions list.
- **Inter-account Transfer**: Deducts `amount` from source balance, adds to destination balance (`beneficiaryAccountId`), and prepends a `DEBIT` transaction to source and a `CREDIT` transaction to the destination transaction list.
- **Invalid account / Insufficient Funds**: Automatically throws `404 Account not found` or `400 Insufficient funds` respectively.

## Schema Guidelines & Endpoint Map
All proxy routes are grouped under `/api` in `src/routes/index.ts`:

- **`/api/status`** (GET, Public): Environment metadata.
- **`/api/pb/accounts`** (GET, Secure): Lists Private and Business accounts.
- **`/api/pb/accounts/:accountId/balance`** (GET, Secure): Account balance.
- **`/api/pb/accounts/:accountId/transactions`** (GET, Secure): Account transactions (Supports parameters `fromDate`, `toDate`, `transactionType`).
- **`/api/pb/beneficiaries`** (GET, Secure): Lists approved EFT beneficiaries.
- **`/api/pb/accounts/:accountId/paymultiple`** (POST, Secure): Pay list of beneficiaries.
  - Body: `{ paymentList: [{ beneficiaryId, amount, myReference, theirReference }] }`
- **`/api/pb/accounts/:accountId/transfermultiple`** (POST, Secure): Transfer to own accounts.
  - Body: `{ transferList: [{ beneficiaryAccountId, amount, myReference, theirReference }] }`

## AI Implementation Directives
- **Security Check**: When writing new routes, verify that the `requireLocalAuth` middleware is mounted to prevent endpoint leakage.
- **Error Propagation**: Wrap controller methods in `try/catch` and forward errors to `next(error)` to allow the central `errorHandler` middleware to format JSON output.
- **Token Cache Limit**: The downstream OAuth bearer token is session-based (expires in 30 minutes). Never serialize this token to disk or send it to the client; cache it solely in-memory inside the `BankService.tokenCache` variable.
